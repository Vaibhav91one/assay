Assay is a self-healing scraper that **abstains when it is not sure**, and
measures how often its heals are wrong.

Every number on this site is read off a file in `results/`, and every command
that produces one is in the repository. Where the number is unflattering it is
still here — see [Limitations](/docs/limitations), which is a page rather than a
footnote on purpose.

Assay uses a small vocabulary and uses it precisely: *held*, *abstain*, *gate*,
*floor* and *lead*, *band*, *episode*, *proof record*. If a word on a screen or
in a response body is doing more work than you expected, the
**[Glossary](/docs/glossary)** says exactly what it means and where it is stored.

## The failure this is about

When a scraper breaks loudly, everyone notices. The request 500s, the selector
returns nothing, the row count drops to zero, and a healer kicks in.

The breaks that matter are the quiet ones. The selector still resolves. The
request still succeeds. The right number of rows still come back. The value is
just wrong.

Here is a real one from this repository's own run log, run 74:

```
baseline_value : "Chicco Polly Highchair Recall"
value_now      : "Skip to main content"
```

Nothing errored. Nothing was empty. A row-count check sees twelve rows before
and twelve rows after. An exception handler never fires. A healer that only
wakes on errors sleeps through it, and the wrong string lands in your database.

## Two things Assay does differently

**It notices without an exception.** Detection does not wait for an error. It
watches the value's shape against a regex and a minimum length, the null rate
against a robust z-score over history, whether the landmark elements it anchored
to still resolve, and whether multiple independent anchors now disagree with
each other. A layout change alone is recorded as context and never counts as a
break on its own, because sites redesign constantly without breaking anything.

**It refuses to guess.** When a field does break, candidates are ranked by
weighted similarity against a stored fingerprint. The winner is published only
if it clears two gates:

```
score > tau (0.60)   AND   score - runner_up > delta (0.16)
```

The second gate is the point. A candidate can look very much like the thing you
lost and still be the wrong answer, if something else looks nearly as much like
it. When two candidates are that close, picking one is a coin flip, and a coin
flip is not a heal. Assay publishes nothing and asks.

<Callout title="Both thresholds were calibrated, not chosen">
  `tools/sweep.ts` scans 110 pairs across an 11 x 10 grid; 0.60 / 0.16 is what
  came out, and the sweep and the benchmark agree cell for cell on the same 153
  cases. They are **fitted values, not constants**, and they are arguments to
  every tool for that reason — see [Limitations §5](/docs/limitations#the-thresholds-are-calibrated-on-this-corpus-and-nowhere-else).
</Callout>

## The measurement

153 cases: ten deterministic mutations applied to real archived pages from three
sites. Ground truth is marked before mutation using an attribute the scorer
never reads, so labelling cannot leak into the score.

Three arms, same cases:

| arm | correct | wrong values published | abstained |
|---|---|---|---|
| naive (first element with the same tag) | 48 | **93** | 12 |
| plain (weighted similarity, no gate) | 117 | **36** | 0 |
| **gated (similarity + margin gate)** | 99 | **0** | 54 |

`npm run bench` reproduces this. Numbers are read from `results/bench.json`.

### The honest trade

The gated arm publishes zero wrong values. It pays for that, and the price is
visible in the per-mutation breakdown.

On `remove_field`, where the element is genuinely gone and the only correct
answer is "I do not know", the ungated healer publishes a wrong value 18 times
out of 18. The gated one abstains 18 out of 18. That is the gate working exactly
as intended.

On `duplicate_similar`, where a near-identical decoy sits beside the real value,
the ungated healer gets 12 right and 6 wrong. The gated one abstains on **all
18**, including the 12 it would have got right. It is over-cautious there, and
36 of the 54 abstentions across the whole benchmark are cases a human now has to
look at that could in principle have been automated.

That is the deal Assay offers: about 24% of breaks land in a review queue
instead of being resolved automatically, and in exchange the wrong-value count
goes from 36 to 0. For product-recall monitoring, where publishing the wrong
hazard for a child's car seat is worse than publishing nothing, that is the
right way round. For a price tracker it might not be. The thresholds are
arguments to every tool, so the trade is yours to set.

### What "correct" means here

Two different notions, reported separately, because the literature conflates
them.

- **Exact node** asks whether the healer found the same DOM element.
- **Value equivalence** asks whether it produced the same string.

The gated arm scores 93 on exact node but 99 on value: six times it picked a
different element that happened to contain the identical text. For scraping,
value is what matters. For test automation, node identity does. Reporting only
the flattering one would be cheating, so both are in `results/bench.json`.

## Where Bright Data fits

Assay is not an alternative to Bright Data. **Bright Data is the fetch layer** —
proxies, anti-bot, and over a thousand prebuilt scrapers addressed by
`dataset_id`. **Assay is a gate on top of it** — it decides whether a value is
safe to publish, and abstains when it is not. `src/runner.ts` takes `fetchPage` as
a *parameter*, which is why a Bright Data delivery and a local fetch reach the
identical detection and gating code.

The clearest evidence that both are needed is `npm run audit`, and it is a real
production run rather than a benchmark we wrote. A Scraper Studio collector
returned 60 records and Bright Data reported the run as **100% successful, 0
failed crawls**:

```
6 of 10 promised fields are not healthy.
Bright Data reported this run as 100% successful.
Nothing in the platform surfaces the 3 fields that never arrived.
```

That is not a criticism of the crawling, which worked — sixty pages fetched from a
site that fights scrapers, none failed. It is a demonstration that **"the job
succeeded" and "the data is right" are different claims**, and the platform can
only answer the first one.

The two also compose directly. Bright Data's self-healing parks at a human
approval gate rather than auto-applying; `src/bd/diffgate.ts` reads the collector
code it proposes and returns a verdict, so `tools/bd-heal.ts --approve` refuses a
repair that would, for instance, rewrite one field to derive from another and
silently retire the only cross-check the break detector had. That rule set is
three rules fitted to one transcript — see
[Limitations](/docs/limitations#the-bright-data-code-gate-is-three-rules-fitted-to-n1).

Nothing in this repository measures Assay *against* Bright Data.
`results/headtohead.jsonl` holds 9 records and all 9 are `system: "assay"`;
`docs/HEADTOHEAD.md` §0 says so and says why.

## The product, in one line

From `docs/FEATURES.md`:

> the scraper withholds the cell it isn't sure about, tells you which rows that
> affects, and asks you exactly one answerable question.

The feature that defines it is **Quarantine**: on abstain, or on an unresolved
detect, hold the cell, publish a labelled hole, and log the reason.

> If only one ships, ship the hole in the data. The hole is the product.

## Reproduce it

Everything runs offline.

```bash
npm install
npm run demo      # 30 seconds: one break heals, one publishes a labelled hole
npm test          # 34 assertions against the real corpus
npm run bench     # the 153-case benchmark
npm run sweep     # the threshold calibration
npm run replay    # replays the full corpus, writes results/events.jsonl
npm run audit     # 6 of 10 promised fields unhealthy, behind a 100%-success run
```

The corpus is committed on purpose: 77 archived HTML captures of three public
recall pages, Jan 2024 to Aug 2026, fetched from the Internet Archive. Without
them none of the numbers above are checkable, which for a project whose entire
claim is a measurement would be worse than the 14 MB.
